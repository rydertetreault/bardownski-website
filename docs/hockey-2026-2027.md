## Connecting tracking later

`getHockeySeason()` in `src/lib/hockey-season.ts` is the explicit current-season data boundary for matches, match details and stats. It intentionally returns `awaiting-setup` with no numbers or matches today. This is a prepared UI, **not an enabled stats integration**.

Before returning `status: "connected"`:

1. Confirm the new game's API, club ID, platform, season identity and source coverage. Do not point at old club 149602 by assumption.
2. Use new **season-namespaced** persistence for matches, deltas, articles and snapshots. Never reuse/reset the existing `match-history:*` data.
3. Return verified new-season `ChelstatsData`, normalized `Match[]` (including player details when available) and a truthful `updatedAt`. Upcoming fixtures require confirmed dates/opponents; do not synthesize them from results.
4. Add unavailable/error handling for the new adapter; never fall back to `FROZEN_CHELSTATS` in the current-season UI. Add an appropriate revalidation policy when the adapter is connected.
5. `chelstatsToSeasonData(members, { season, date })` supports explicit current-season labels. Its default remains the 2025–2026 archive for existing consumers.
6. Keep historical records/awards frozen. The record book is currently snapshot-backed; supporting new records requires a separate verified data update.
7. Audit cron routes before enabling jobs. Weekly updates remain explicitly paused; legacy match sync and its `SEASON_LIVE` gate are unchanged. The old fetch function **still returns frozen data**. Do not enable either job merely because the UI says 2026–2027.

The current MVP view uses the existing position-adjusted model, minimum five games per scored role, shared ranks on exact ties. The homepage uses Variation 4’s archived model-score disclosures and previous-award details. It does not display simulated betting odds or declare an MVP before the season ends.
